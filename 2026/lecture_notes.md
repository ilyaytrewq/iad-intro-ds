# Краткое повторение: лекции 1-6

## Лекция 1. Введение

Машинное обучение - это восстановление сложной зависимости по конечному числу примеров. Если явную формулу выписать трудно, но есть объекты с известными ответами, можно обучать модель.

Основные обозначения:

- `x` - объект.
- `X_space` или `mathbb X` - пространство объектов.
- `y` - ответ, целевая переменная, target.
- `Y_space` или `mathbb Y` - пространство ответов.
- `X = {(x_i, y_i)}_{i=1}^l` - обучающая выборка.
- `l` - размер выборки.
- `d` - число признаков.
- `x = (x_1, ..., x_d)` - признаковое описание объекта.
- `a(x)` - алгоритм, модель, функция предсказания.

Функция потерь `L(y, a)` показывает, насколько плох конкретный ответ модели на одном объекте. Функционал ошибки `Q(a, X)` показывает качество модели на выборке. Обучение обычно записывается как

```text
a* = argmin_{a in A} Q(a, X),
```

где `A` - семейство моделей, среди которых ищем лучшую.

Важно: метрика качества должна соответствовать бизнес-требованию. Это не техническая мелочь, а часть постановки задачи.

## Лекция 2. k ближайших соседей

Типы задач:

- Регрессия: вещественный ответ, `Y = R`.
- Классификация: конечное число классов.
- Бинарная классификация: `Y = {-1, +1}`.
- Многоклассовая классификация: `Y = {1, ..., K}`.
- Multi-label: объект может принадлежать нескольким классам.
- Ранжирование: нужно упорядочить объекты по релевантности.
- Кластеризация: ответов нет, нужно найти группы похожих объектов.

Типы признаков:

- Бинарные: `{0, 1}`.
- Вещественные.
- Категориальные: неупорядоченное множество значений.
- Порядковые: значения упорядочены.
- Более сложные: тексты, изображения, звук.

Гипотеза компактности: если два объекта похожи, то ответы на них тоже похожи. На ней основан kNN.

kNN для классификации:

1. На обучении просто запоминаем выборку.
2. Для нового объекта сортируем обучающие объекты по расстоянию.
3. Берем `k` ближайших.
4. Возвращаем самый частый класс:

```text
a(x) = argmax_{y in Y} sum_{i=1}^k [y_i = y].
```

Метрики расстояния:

- Евклидова: `rho(x,z) = sqrt(sum_j (x_j - z_j)^2)`.
- Манхэттенская: `rho(x,z) = sum_j |x_j - z_j|`.
- Минковского: `rho_p(x,z) = (sum_j |x_j - z_j|^p)^{1/p}`.
- Для категориальных признаков можно считать число несовпадающих координат.

## Лекция 3. Оценка качества, валидация, взвешенный kNN

Для классификации частая потеря:

```text
L(y, a) = [a != y].
```

Доля ошибок:

```text
error_rate = (1/l) sum_i [a(x_i) != y_i].
```

Доля правильных ответов:

```text
accuracy = (1/l) sum_i [a(x_i) = y_i].
```

Важно: `accuracy` - это не precision. В русских материалах курса precision называют точностью, а accuracy - долей правильных ответов.

Проблема accuracy: на несбалансированных данных она может быть высокой у бесполезной модели. Пример: если 950 здоровых и 50 больных, модель "все здоровы" дает 95% accuracy, но не находит больных.

Гиперпараметры нельзя подбирать по обучающей выборке. Для выбора `k`, метрики, ширины окна и т.п. нужны дополнительные данные.

Разбиения данных:

- Обучающая выборка: строим модель.
- Валидационная выборка: подбираем гиперпараметры.
- Тестовая выборка: финально оцениваем качество.

Кросс-валидация:

- Делим выборку на `n` фолдов.
- По очереди обучаемся на `n-1` фолдах и проверяемся на оставшемся.
- Обычно берут 3, 5 или 10 фолдов.
- Leave-one-out - крайний случай, когда фолдов столько же, сколько объектов.

Взвешенный kNN:

```text
a(x) = argmax_{y in Y} sum_i w_i [y_i = y].
```

Вес можно задавать через ядро:

```text
w_i = K(rho(x, x_i) / h),
```

где `K` - ядро, `h` - ширина окна. Чем меньше `h`, тем сильнее влияние самых близких объектов.

kNN для регрессии:

```text
a(x) = (1/k) sum_{i=1}^k y_i.
```

С весами:

```text
a(x) = sum_i w_i y_i / sum_i w_i.
```

Плюсы kNN: простое обучение, мало гиперпараметров, хорошо работает, если похожие объекты действительно имеют похожие ответы.

Минусы kNN: нужно хранить всю выборку, долго искать соседей, мало способов гибко настраивать модель.

## Лекция 4. Линейная регрессия

Линейная регрессия для одного признака:

```text
a(x) = w_1 x + w_0.
```

Для многих признаков:

```text
a(x) = w_0 + w_1 x_1 + ... + w_d x_d.
```

Если добавить фиктивный признак `x_0 = 1`, можно писать короче:

```text
a(x) = <w, x>.
```

Линейность относится к весам, а не обязательно к исходным признакам. Модель может быть линейной по признакам `x`, `x^2`, `log(x)`, one-hot признакам и т.д.

Категориальные признаки кодируют через one-hot:

```text
район = ЦАО -> (1, 0, 0)
район = ЮАО -> (0, 1, 0)
район = САО -> (0, 0, 1)
```

Числовые признаки можно бинаризовать по интервалам, а можно добавлять полиномиальные признаки и взаимодействия.

В матричной форме для всех объектов:

```text
predictions = Xw
errors = Xw - y
MSE = (1/l) ||Xw - y||^2
```

Градиент MSE:

```text
grad Q(w) = (2/l) X^T (Xw - y).
```

Аналитическое решение нормальных уравнений:

```text
w = (X^T X)^(-1) X^T y.
```

Проблемы аналитического решения: `X^T X` может быть вырожденной или почти вырожденной, а при большом числе признаков обращение матрицы дорогое.

## Лекция 5. Регуляризация и градиентный спуск

Большие коэффициенты в линейной модели - частый симптом переобучения: модель может запоминать обучающую выборку и становиться слишком чувствительной к маленьким изменениям признаков.

Ridge-регрессия, или L2-регуляризация:

```text
(1/l) sum_i (<w, x_i> - y_i)^2 + lambda ||w||_2^2 -> min_w.
```

`lambda` - коэффициент регуляризации. Чем он больше, тем сильнее штраф за большие веса.

Аналитическое решение Ridge:

```text
w = (X^T X + lambda I)^(-1) X^T y.
```

LASSO, или L1-регуляризация:

```text
(1/l) sum_i (<w, x_i> - y_i)^2 + lambda ||w||_1 -> min_w.
```

LASSO может занулять веса и тем самым выполнять отбор признаков.

Интерпретация весов корректна только после масштабирования признаков. Если площадь измерить в квадратных метрах или сантиметрах, вес изменится, хотя смысл признака тот же.

Стандартизация признака:

```text
x'_ij = (x_ij - mu_j) / sigma_j,
```

где `mu_j` и `sigma_j` считаются только по обучающей выборке.

Градиентный спуск:

```text
w_t = w_{t-1} - eta grad Q(w_{t-1}).
```

`eta` - длина шага, learning rate. Если шаг слишком большой, метод может разойтись; если слишком маленький, будет очень медленно.

Остановка:

- веса почти не меняются;
- градиент близок к нулю;
- качество на валидации перестало улучшаться.

Градиентный спуск в общем случае находит локальный минимум. Для невыпуклых задач может помогать мультистарт.

## Лекция 6. Стохастический градиентный спуск и первые функции потерь

У полного градиентного спуска один шаг требует пройти по всей выборке. Это дорого на больших данных.

Стохастический градиентный спуск (SGD) оценивает градиент по одному случайному объекту:

```text
w_t = w_{t-1} - eta_t grad L(y_i, a(x_i)).
```

Mini-batch SGD берет не один объект, а небольшой случайный батч:

```text
w_t = w_{t-1} - eta_t (1/m) sum_{i in batch} grad L(y_i, a(x_i)).
```

SGD шумный, но дешевый на шаг. Mini-batch обычно более устойчивый компромисс.

Лекция также подводит к функциям потерь в регрессии:

- MSE сильно штрафует большие ошибки и чувствительна к выбросам.
- MAE штрафует линейно и обычно устойчивее к выбросам.

## Лекция 7. Функции потерь в регрессии и линейная классификация

### Функции потерь в регрессии

MSE, среднеквадратичная ошибка:

```text
L(y, a) = (a - y)^2
Q(a, X) = (1/l) sum_i (a(x_i) - y_i)^2
```

Смысл: большие ошибки штрафуются квадратично. Поэтому MSE сильно тянется к выбросам: один объект с огромной ошибкой может доминировать в функционале.

MAE, средняя абсолютная ошибка:

```text
L(y, a) = |a - y|
Q(a, X) = (1/l) sum_i |a(x_i) - y_i|
```

Смысл: ошибка штрафуется линейно. MAE менее чувствительна к выбросам, чем MSE, но хуже оптимизируется градиентными методами из-за недифференцируемости в нуле.

Huber loss:

```text
L_delta(y, a) =
    1/2 (y - a)^2,                 если |y - a| < delta
    delta (|y - a| - delta / 2),   если |y - a| >= delta
```

Смысл: около нуля ведет себя как MSE, на больших ошибках как MAE. Это компромисс: гладкая в центре и более устойчивая к выбросам.

MAPE, mean absolute percentage error:

```text
L(y, a) = |y - a| / |y|
Q(a, X) = (100% / l) sum_i |a(x_i) - y_i| / |y_i|
```

Особенности:

- измеряет относительную ошибку;
- плохо работает при `y` около нуля;
- при неотрицательных прогнозах несимметрична: недопрогноз ограничен, перепрогноз может штрафоваться очень сильно.

SMAPE, symmetric mean absolute percentage error:

```text
L(y, a) = |y - a| / ((|y| + |a|) / 2)
Q(a, X) = (100% / l) sum_i |y_i - a(x_i)| / ((|y_i| + |a(x_i)|) / 2)
```

Смысл: относительная ошибка, но знаменатель зависит и от ответа, и от прогноза, поэтому асимметрия меньше, чем у MAPE.

Как выбирать:

- Если большие ошибки особенно опасны - MSE.
- Если есть выбросы - MAE или Huber.
- Если важна относительная ошибка - MAPE или SMAPE, но нужно следить за нулями и малыми значениями `y`.

### Линейный классификатор

В бинарной классификации:

```text
Y = {-1, +1}
```

Линейный классификатор:

```text
a(x) = sign(<w, x>).
```

Свободный коэффициент можно включить в `w`, если добавить признак `x_0 = 1`.

Геометрия:

- ` <w, x> = 0 ` - разделяющая гиперплоскость.
- ` <w, x> > 0 ` - одна сторона гиперплоскости.
- ` <w, x> < 0 ` - другая сторона.
- Чем больше `|<w, x>|`, тем дальше объект от гиперплоскости.

Расстояние от точки до гиперплоскости:

```text
distance = |<w, x>| / ||w||.
```

Отступ объекта:

```text
M_i = y_i <w, x_i>.
```

Интерпретация отступа:

- `M_i > 0`: классификатор ответил верно.
- `M_i < 0`: классификатор ошибся.
- Чем больше положительный отступ, тем увереннее правильное предсказание.
- Чем более отрицательный отступ, тем увереннее ошибка.

Можно вводить порог:

```text
a(x) = sign(<w, x> - t).
```

Порог часто подбирают под нужную метрику после обучения.

### Обучение линейного классификатора

Естественная потеря классификации:

```text
L(y, a) = [a != y].
```

Для линейного классификатора через отступ:

```text
[a(x_i) != y_i] = [M_i < 0].
```

Проблема: индикатор `[M < 0]` недифференцируемый, поэтому напрямую оптимизировать сложно.

Идея: заменить индикатор верхней дифференцируемой или почти дифференцируемой оценкой.

Примеры верхних оценок:

- Логистическая:

```text
L(M) = log(1 + exp(-M)).
```

- Hinge loss:

```text
L(M) = max(0, 1 - M).
```

- Экспоненциальная:

```text
L(M) = exp(-M).
```

Для логистической функции потерь задача:

```text
(1/l) sum_i log(1 + exp(-y_i <w, x_i>)) -> min_w.
```

Градиент:

```text
grad Q(w) = -(1/l) sum_i y_i x_i / (1 + exp(y_i <w, x_i>)).
```

Шаг градиентного спуска:

```text
w_t = w_{t-1} + eta (1/l) sum_i y_i x_i / (1 + exp(y_i <w_{t-1}, x_i>)).
```

С регуляризацией:

```text
(1/l) sum_i log(1 + exp(-y_i <w, x_i>)) + lambda ||w||^2 -> min_w.
```

Важно: обычно свободный коэффициент не регуляризуют.

### Accuracy и несбалансированные выборки

Accuracy:

```text
accuracy = (1/l) sum_i [a(x_i) = y_i].
```

На несбалансированных данных высокая accuracy может означать просто угадывание самого частого класса. Если доля крупнейшего класса `q_max`, то для разумной модели accuracy обычно стоит сравнивать как минимум с `q_max`, а не с 0.5.

## Лекция 8. Метрики классификации и метрики ранжирования

### Матрица ошибок

Для положительного класса `+1`:

|                         | `y = +1` | `y = -1` |
|-------------------------|----------|----------|
| `a(x) = +1`             | TP       | FP       |
| `a(x) = -1`             | FN       | TN       |

Расшифровка:

- TP, true positive: модель нашла положительный объект.
- FP, false positive: модель ошибочно назвала отрицательный объект положительным.
- FN, false negative: модель пропустила положительный объект.
- TN, true negative: модель верно отвергла отрицательный объект.

### Precision и recall

Precision, точность:

```text
precision = TP / (TP + FP).
```

Вопрос: можно ли доверять модели, когда она говорит `+1`?

Recall, полнота:

```text
recall = TP / (TP + FN).
```

Вопрос: какую долю настоящих положительных объектов модель нашла?

Типичный конфликт:

- Высокий порог: меньше объектов получают `+1`, precision выше, recall ниже.
- Низкий порог: больше объектов получают `+1`, recall выше, precision ниже.

Примеры постановки:

- Кредитный скоринг: может быть ограничение `precision >= 0.95`, а среди таких моделей максимизируем recall.
- Медицинская диагностика: может быть ограничение `recall >= 0.8`, а среди таких моделей максимизируем precision.
- Антифрод: высокая precision означает редко блокируем нормальные транзакции, высокая recall означает редко пропускаем мошенничество.

### Объединение precision и recall

Арифметическое среднее может быть плохим: модель с `precision = 0.1`, `recall = 1` получит среднее 0.55, как и модель с `precision = recall = 0.55`, хотя первая может быть практически бесполезной.

Минимум:

```text
min(precision, recall)
```

строго наказывает провал одной метрики, но не различает ситуации, где одна метрика стала лучше при неизменной другой.

F-мера:

```text
F1 = 2 * precision * recall / (precision + recall).
```

Это гармоническое среднее precision и recall. Оно сильно падает, если одна из метрик мала.

F-beta:

```text
F_beta = (1 + beta^2) * precision * recall / (beta^2 * precision + recall).
```

Интерпретация:

- `beta < 1`: важнее precision.
- `beta > 1`: важнее recall.

Геометрическое среднее:

```text
G = sqrt(precision * recall).
```

Тоже учитывает обе метрики, но ведет себя иначе, чем F-мера.

### Порог и оценка принадлежности

Линейный классификатор можно писать как:

```text
a(x) = sign(<w, x> - t).
```

`<w, x>` - оценка принадлежности положительному классу, а `t` - порог. Если модель возвращает score `b(x)`, то конкретный классификатор получается только после выбора порога.

Плохое качество при одном пороге еще не всегда означает плохую модель: возможно, неправильно выбран порог.

### PR-кривая

PR-кривая строится по всем возможным порогам:

- ось X: recall;
- ось Y: precision;
- каждая точка соответствует своему порогу.

Свойства:

- Левая точка обычно около `(0, 1)`.
- Правая точка при очень низком пороге имеет `recall = 1`, а precision равна доле положительного класса.
- AUC-PRC - площадь под PR-кривой.

PR-кривая особенно полезна на несбалансированных данных и когда задача формулируется через precision/recall.

### ROC-кривая

ROC-кривая:

- ось X: false positive rate;
- ось Y: true positive rate.

```text
FPR = FP / (FP + TN)
TPR = TP / (TP + FN) = recall
```

Свойства:

- Идеальный классификатор проходит через точку `(0, 1)`.
- Случайный классификатор имеет AUC-ROC около 0.5.
- Идеальный классификатор имеет AUC-ROC = 1.

Интерпретация AUC-ROC: примерно доля правильно упорядоченных пар "положительный объект выше отрицательного".

Коэффициент Джини:

```text
Gini = 2 * (AUC-ROC - 0.5).
```

### AUC-ROC против AUC-PRC

AUC-ROC мало меняется при изменении баланса классов, потому что FPR и TPR нормируются отдельно по отрицательным и положительным объектам.

AUC-PRC зависит от баланса классов, потому что precision зависит от числа отрицательных объектов. На сильно несбалансированных данных AUC-ROC может выглядеть хорошо, хотя precision у полезного порога будет очень низким.

Практическое правило:

- Если данные сильно несбалансированы и важны найденные положительные объекты, смотреть PR-кривую и AUC-PRC.
- Если нужно оценить качество ранжирования более независимо от баланса, смотреть ROC и AUC-ROC.

## Лекция 9. Логистическая регрессия и метод опорных векторов

### Вероятности в классификации

Модель `b(x)` предсказывает вероятности, если среди объектов, для которых `b(x) = p`, доля положительных действительно равна `p`.

Зачем нужны вероятности:

- кредитный скоринг: выдавать кредит, если вероятность возврата выше порога;
- реклама: оценивать ожидаемую прибыль `c(x) * b(x)`;
- отток клиентов: оценивать риск ухода;
- медицинская диагностика: оценивать риск заболевания;
- поиск и ранжирование: оценивать релевантность.

Линейный классификатор дает score:

```text
s(x) = <w, x>.
```

Чтобы получить число на `[0, 1]`, применяют сигмоиду:

```text
sigma(z) = 1 / (1 + exp(-z)).
b(x) = sigma(<w, x>).
```

### Log-loss и логистическая регрессия

Если `y = +1`, хотим `sigma(<w,x>) -> 1`.

Если `y = -1`, хотим `sigma(<w,x>) -> 0`.

Log-loss:

```text
L(y, z) = -[y = +1] log z - [y = -1] log(1 - z),
```

где `z = sigma(<w,x>)`.

После преобразований получается логистическая функция потерь через отступ:

```text
L(y, <w,x>) = log(1 + exp(-y <w,x>)).
```

Задача логистической регрессии:

```text
(1/l) sum_i log(1 + exp(-y_i <w,x_i>)) -> min_w.
```

Смысл: логистическая регрессия обучает линейную модель так, чтобы после сигмоиды ее прогнозы были похожи на вероятности.

### Калибровочная кривая

Чтобы проверить, похожи ли предсказания на вероятности:

1. Разбиваем отрезок `[0, 1]` на корзины.
2. Для каждой корзины берем объекты, у которых `b(x)` попал в нее.
3. Считаем реальную долю положительных в корзине.
4. Сравниваем с предсказанными вероятностями.

Идеально откалиброванная модель лежит около диагонали.

### Hinge loss и идея SVM

Hinge loss:

```text
L(M) = max(0, 1 - M),
M_i = y_i <w, x_i>.
```

SVM основан на идее максимизации отступа классификатора: хочется провести гиперплоскость так, чтобы ближайшие объекты были как можно дальше от нее.

В линейно разделимом случае:

- есть гиперплоскость без ошибок;
- масштаб `w` и свободного коэффициента можно менять без изменения знака;
- вводится нормировка, при которой минимальный функциональный отступ равен 1;
- тогда геометрический отступ равен `1 / ||w||`.

Значит, максимизация отступа эквивалентна минимизации нормы весов.

Базовая идея SVM для разделимого случая:

```text
||w||^2 -> min
y_i (<w, x_i> + w_0) >= 1 для всех i.
```

## Лекция 10. SVM, многоклассовая классификация, нелинейность и деревья

### Soft-margin SVM

Если выборка линейно неразделима, строгие ограничения `y_i(<w,x_i> + w_0) >= 1` выполнить нельзя. Вводят slack-переменные `xi_i >= 0`, которые разрешают нарушения:

```text
y_i (<w, x_i> + w_0) >= 1 - xi_i
xi_i >= 0
```

Оптимизационная задача:

```text
||w||^2 + C sum_i xi_i -> min.
```

`C` управляет компромиссом:

- маленькое `C`: модель терпимее к нарушениям, сильнее стремится к большому отступу;
- большое `C`: модель сильнее штрафует ошибки и нарушения отступа.

Так как

```text
xi_i >= max(0, 1 - y_i(<w,x_i> + w_0)),
```

задачу можно записать как hinge loss плюс регуляризация:

```text
C sum_i max(0, 1 - y_i(<w,x_i> + w_0)) + ||w||^2 -> min.
```

Логистическая регрессия и SVM похожи тем, что обучают линейную границу через верхнюю оценку ошибки. Главное различие в функции потерь и интерпретации:

- логистическая регрессия естественно связана с вероятностями и log-loss;
- SVM связан с максимизацией отступа и hinge loss.

### Многоклассовая классификация

Пусть классы:

```text
Y = {1, ..., K}.
```

One-vs-all:

1. Для каждого класса `k` обучаем бинарный классификатор "класс k против всех остальных".
2. Каждая модель выдает score принадлежности своему классу.
3. Итог:

```text
a(x) = argmax_k a_k(x).
```

Особенности:

- нужно обучить `K` моделей;
- каждая модель при обучении не знает, что ее score будут сравнивать со score других моделей.

All-vs-all:

1. Для каждой пары классов `(k, m)` обучаем классификатор только на объектах этих двух классов.
2. На применении классификаторы голосуют.
3. Итоговый класс - победитель голосования.

Особенности:

- нужно порядка `K^2` моделей;
- каждая модель обучается на меньшей выборке.

Accuracy и error rate напрямую обобщаются на многоклассовый случай:

```text
error_rate = (1/l) sum_i [a(x_i) != y_i]
accuracy = (1/l) sum_i [a(x_i) = y_i].
```

Для precision/recall/F-меры в многоклассовом случае нужны усреднения.

Микро-усреднение:

- считаем `TP_k`, `FP_k`, `FN_k`, `TN_k` для каждого класса;
- суммируем по классам;
- подставляем суммарные значения в формулу метрики;
- крупные классы вносят больший вклад.

Макро-усреднение:

- считаем метрику отдельно для каждого класса;
- усредняем значения по классам;
- размеры классов игнорируются.

### Как делать нелинейные модели из линейных

Если связь между признаками и ответом нелинейна, можно добавить новые признаки:

- полиномиальные признаки: `x_j^2`, `x_j x_k`, степени выше;
- бинаризованные признаки: интервалы вроде `30 < площадь < 50`;
- логарифмы, синусы и другие преобразования.

Проблема: число признаков быстро растет. Например, при 10 исходных признаках полиномиальных признаков степени 4 уже сотни.

Бинаризация и логические признаки часто интерпретируемее, чем голые полиномиальные взаимодействия.

### Переход к решающим деревьям

Решающие деревья строят модель из логических правил:

```text
если этаж < 3 и расстояние до метро < 200, то прогноз такой-то.
```

Внутренние вершины дерева - предикаты, например `x_j < t`.

Листья - прогнозы:

- для регрессии: число;
- для классификации: класс или вероятности классов.

Дерево легко строит нелинейные зависимости и взаимодействия признаков, потому что путь от корня к листу является логическим правилом.

## Лекция 11. Решающие деревья

### Вид модели

Дерево разбивает пространство признаков на области `R_1, ..., R_m`. Каждая область соответствует листу, а в листе прогноз константный:

```text
a(x) = sum_{j=1}^m c_j [x in R_j].
```

Для регрессии прогноз в листе обычно среднее:

```text
c_j = (1 / |R_j|) sum_{(x_i,y_i) in R_j} y_i.
```

Для классификации прогноз в листе - самый частый класс:

```text
c_j = argmax_{k in Y} sum_{(x_i,y_i) in R_j} [y_i = k].
```

Можно также возвращать вероятности классов:

```text
p_{jk} = (1 / |R_j|) sum_{(x_i,y_i) in R_j} [y_i = k].
```

Дерево можно воспринимать как модель, которая создает новые бинарные признаки `[x in R_j]`, а затем делает по ним простую линейную модель.

### Как выбирать разбиения в классификации

В вершине дерева есть набор объектов `R`. Нужно выбрать признак `j` и порог `t`, чтобы разбиение было как можно лучше:

```text
R_left = {(x_i, y_i) in R : x_{ij} < t}
R_right = {(x_i, y_i) in R : x_{ij} >= t}
```

Идея: хорошее разбиение уменьшает "хаотичность" дочерних вершин.

Энтропия распределения классов:

```text
H(p_1, ..., p_K) = - sum_k p_k log p_k.
```

Смысл:

- максимум, когда классы перемешаны равномерно;
- 0, когда в вершине только один класс.

Критерий Джини:

```text
G(p_1, ..., p_K) = sum_k p_k (1 - p_k) = 1 - sum_k p_k^2.
```

Смысл: вероятность ошибки случайного классификатора, который выдает класс `k` с вероятностью `p_k`. Также связан с числом пар объектов разных классов.

Взвешенный критерий качества разбиения:

```text
Q(R, j, t) =
    (|R_left| / |R|) H(R_left)
  + (|R_right| / |R|) H(R_right)
  -> min.
```

Эквивалентно можно максимизировать уменьшение impurity:

```text
Gain = H(R) - (|R_left| / |R|) H(R_left) - (|R_right| / |R|) H(R_right).
```

Почему нужны веса `|R_left| / |R|` и `|R_right| / |R|`: иначе маленький чистый лист мог бы выглядеть слишком хорошо, хотя почти вся выборка осталась хаотичной.

### Разбиения в регрессии

В регрессии "хаотичность" вершины измеряют дисперсией ответов:

```text
H(R) = (1 / |R|) sum_{(x_i,y_i) in R} (y_i - mean_R y)^2.
```

Хорошее разбиение делает ответы внутри дочерних вершин более однородными.

### Жадное построение дерева

Оптимально перебрать все деревья невозможно: слишком много вариантов. Поэтому дерево строят жадно.

Алгоритм:

1. В корень помещаем всю выборку.
2. Если выполнен критерий останова, делаем вершину листом.
3. Ищем лучший предикат `(j, t)`.
4. Делим объекты на левую и правую дочерние вершины.
5. Рекурсивно повторяем для потомков.

Критерии останова:

- максимальная глубина;
- максимальное число листьев;
- минимальное число объектов в вершине;
- минимальное уменьшение impurity;
- все объекты в вершине одного класса;
- другие ограничения.

Дерево можно строить до идеального запоминания обучающей выборки, если нет одинаковых объектов с разными ответами. Поэтому деревья легко переобучаются.

### Неустойчивость деревьев

Деревья неустойчивы: небольшое изменение обучающей выборки может поменять верхние разбиения, а значит и всю структуру дерева.

Это плохо для одной модели, но полезно для композиций: если построить много разных деревьев и усреднить или проголосовать, можно уменьшить разброс.

### Композиции моделей

Для классификации majority vote:

```text
a(x) = argmax_{y in Y} sum_{n=1}^N [b_n(x) = y].
```

Для регрессии усреднение:

```text
a(x) = (1/N) sum_{n=1}^N b_n(x).
```

Интуиция: усреднение независимых ошибок повышает устойчивость, как усреднение измерений.

## Лекция 12. Композиции моделей, бэггинг, смещение и разброс

### Общая идея композиции

Есть базовые модели:

```text
b_1(x), ..., b_N(x).
```

Для классификации объединяем их голосованием:

```text
a_N(x) = argmax_{y in Y} sum_{n=1}^N [b_n(x) = y].
```

Для регрессии объединяем усреднением:

```text
a_N(x) = (1/N) sum_{n=1}^N b_n(x).
```

Базовые модели должны быть хотя бы немного лучше случайного угадывания и желательно делать разные ошибки.

Два способа получить разные модели:

- обучить независимо на разных подвыборках;
- обучать последовательно, чтобы каждая следующая исправляла ошибки предыдущих.

Первый путь ведет к бэггингу, второй - к бустингу.

### Бэггинг

Bagging = bootstrap aggregating.

Алгоритм:

1. Для каждой базовой модели генерируем bootstrap-выборку.
2. Обучаем модель независимо.
3. Объединяем модели усреднением или голосованием.

Bootstrap:

- выборка с возвращением;
- из `l` исходных объектов выбираем `l` раз;
- объект может попасть несколько раз;
- примерно 63.2% объектов будут уникальными;
- повтор объекта можно понимать как увеличение его веса.

### Случайные подпространства

Еще один способ рандомизации: обучать базовые модели на случайных подмножествах признаков.

Плюс: модели становятся менее похожими.

Минус: если есть критически важные признаки, модель без них может стать слабой.

### Смещение и разброс

Ошибка модели на уровне идеи складывается из:

- noise: шум данных, который нельзя устранить моделью;
- bias: смещение, неспособность семейства моделей приблизить истинную зависимость;
- variance: разброс, чувствительность модели к изменению обучающей выборки.

Линейные модели обычно более устойчивые, но могут иметь высокое смещение, если зависимость сложная.

Деревья могут иметь низкое смещение, но высокий разброс: они гибкие и сильно реагируют на изменения выборки.

### Почему бэггинг помогает

Бэггинг в основном снижает variance, но почти не меняет bias базовой модели.

Если базовые модели независимы, разброс усреднения падает примерно в `N` раз. Если модели сильно коррелируют, эффект слабее.

Ключевая мысль: бэггинг особенно хорош для неустойчивых моделей, например для глубоких деревьев.

## Лекция 13. Случайные леса и градиентный бустинг

### Случайный лес

Случайный лес - бэггинг над решающими деревьями плюс дополнительная рандомизация признаков.

Алгоритм Random Forest:

Для `n = 1, ..., N`:

1. Сгенерировать bootstrap-выборку.
2. Построить решающее дерево `b_n(x)` на этой выборке.
3. Дерево строить до заданного критерия останова, например пока в листе не останется не более `n_min` объектов.
4. В каждой вершине искать лучшее разбиение не по всем `d` признакам, а по случайному подмножеству из `q` признаков.

Важно: случайное подмножество признаков выбирается заново в каждой вершине, а не один раз на дерево.

Итог для регрессии:

```text
a(x) = (1/N) sum_{n=1}^N b_n(x).
```

Итог для классификации:

```text
a(x) = argmax_{y in Y} sum_{n=1}^N [b_n(x) = y].
```

Зачем выбирать случайные признаки: уменьшить корреляцию между деревьями. Если деревья слишком похожи, усреднение почти ничего не дает.

Типичные рекомендации для размера подмножества признаков:

- регрессия: около `d / 3`;
- классификация: около `sqrt(d)`.

Свойства:

- ошибка сначала убывает с ростом `N`, потом выходит на плато;
- случайный лес обычно не переобучается просто от увеличения числа деревьев;
- метод часто работает хорошо "из коробки".

### Out-of-bag оценка

Каждое дерево обучается примерно на 63.2% уникальных объектов. Остальные объекты для этого дерева являются out-of-bag.

Идея OOB:

1. Для каждого объекта берем только деревья, которые не видели его при обучении.
2. Усредняем или голосуем их прогнозы.
3. Считаем качество.

Так можно оценить обобщающую способность без отдельной тестовой выборки, хотя финальный тест все равно полезен для честной оценки.

### Важность признаков

Перестановочная важность:

1. Берем тестовую или OOB-выборку.
2. Перемешиваем один столбец признака `j`.
3. Считаем качество модели.
4. Чем сильнее качество упало, тем важнее признак.

Смысл: если разрушить связь признака с ответом и модель сильно испортилась, признак был полезен.

### Идея бустинга

Проблемы бэггинга:

- если базовая модель сильно смещена, усреднение не исправит bias;
- много больших базовых моделей дорого хранить и применять.

Бустинг:

- базовые модели обучаются последовательно;
- каждая следующая модель исправляет ошибки уже построенной композиции;
- обычно берут простые базовые модели.

Композиция:

```text
a_N(x) = sum_{n=1}^N b_n(x).
```

На шаге `N` хочется выбрать `b_N`, чтобы уменьшить ошибку:

```text
(1/l) sum_i L(y_i, a_{N-1}(x_i) + b_N(x_i)) -> min_{b_N}.
```

Но напрямую обучать дерево под такой функционал трудно, особенно для произвольной функции потерь.

### Бустинг для MSE

Для MSE:

```text
L(y, z) = (z - y)^2.
```

На шаге `N`:

```text
sum_i (a_{N-1}(x_i) + b_N(x_i) - y_i)^2 -> min.
```

Это то же самое, что обучать новую модель на остатки:

```text
s_i^{(N)} = y_i - a_{N-1}(x_i).
```

Задача базовой модели:

```text
sum_i (b_N(x_i) - s_i^{(N)})^2 -> min.
```

Интерпретация: если текущая композиция недопрогнозировала объект, остаток положительный; если перепрогнозировала, остаток отрицательный.

Бустинг может переобучаться, поэтому нужно следить за ошибкой на валидации или тесте и ограничивать число итераций, глубину деревьев, learning rate.

### Почему нельзя всегда обучаться на обычные остатки

Для произвольной функции потерь остатки `y_i - a_{N-1}(x_i)` могут не отражать, как именно нужно менять прогноз.

Пример с логистической потерей: если просто учиться на разность между классом и текущим ответом, не учитывается, насколько сильно модель уже ошибается и как именно устроена log-loss.

Нужно учитывать производную функции потерь.

### Градиентный бустинг

На объекте `x_i` текущий прогноз:

```text
z_i = a_{N-1}(x_i).
```

Хотим понять, куда сдвинуть прогноз, чтобы уменьшить потерю. Для этого считаем антиградиент:

```text
s_i^{(N)} = - d/dz L(y_i, z) |_{z = a_{N-1}(x_i)}.
```

`s_i^{(N)}` называют псевдоостатком или сдвигом.

Новая базовая модель обучается приближать эти сдвиги:

```text
(1/l) sum_i (b_N(x_i) - s_i^{(N)})^2 -> min_{b_N}.
```

Смысл:

- знак `s_i` показывает, в какую сторону менять прогноз;
- величина `s_i` показывает, насколько сильно полезно менять прогноз;
- если потеря почти не меняется от сдвига, объект почти не влияет на новую модель.

Градиентный бустинг - это как градиентный спуск в пространстве ответов модели на обучающей выборке.

### Примеры псевдоостатков

Для MSE с `L(y,z) = 1/2 (z - y)^2`:

```text
s_i = y_i - a_{N-1}(x_i).
```

То есть получаются обычные остатки.

Для логистической функции потерь:

```text
L(y,z) = log(1 + exp(-y z)).
```

Антиградиент:

```text
s_i = y_i / (1 + exp(y_i a_{N-1}(x_i))).
```

Интерпретация:

- если отступ `y_i a_{N-1}(x_i)` большой положительный, модель уже уверенно права, `s_i` близок к 0;
- если отступ большой отрицательный, модель уверенно ошибается, `s_i` по модулю близок к 1;
- новая модель фокусируется на объектах, где композицию нужно заметно поправить.

Для асимметричной функции потерь производная меняется в зависимости от того, недопрогнозировали или перепрогнозировали. Это позволяет явно учитывать, что разные типы ошибок имеют разную цену.

### Random Forest против Gradient Boosting

Random Forest:

- независимые деревья;
- снижает variance;
- устойчивый, часто мало гиперпараметров;
- увеличение числа деревьев обычно приводит к плато, а не к резкому переобучению.

Gradient Boosting:

- деревья строятся последовательно;
- исправляет ошибки предыдущей композиции;
- может снижать bias;
- обычно чувствительнее к гиперпараметрам и может переобучаться;
- важны число итераций, learning rate, глубина деревьев, регуляризация.

# Мини-шпаргалка формул

## Регрессия

```text
MSE = (1/l) sum_i (a(x_i) - y_i)^2
MAE = (1/l) sum_i |a(x_i) - y_i|
MAPE = (100%/l) sum_i |a(x_i) - y_i| / |y_i|
SMAPE = (100%/l) sum_i |a(x_i)-y_i| / ((|y_i|+|a(x_i)|)/2)
```

## Линейная модель

```text
a(x) = <w, x>
M_i = y_i <w, x_i>
distance_to_hyperplane = |<w,x>| / ||w||
```

## Логистическая регрессия

```text
sigma(z) = 1 / (1 + exp(-z))
L(y,z) = log(1 + exp(-y z))
Q(w) = (1/l) sum_i log(1 + exp(-y_i <w,x_i>))
```

## SVM

```text
hinge(M) = max(0, 1 - M)
soft_margin_objective =
    C sum_i max(0, 1 - y_i(<w,x_i> + w_0)) + ||w||^2
```

## Классификация

```text
accuracy = (TP + TN) / (TP + FP + FN + TN)
precision = TP / (TP + FP)
recall = TP / (TP + FN)
F1 = 2 * precision * recall / (precision + recall)
F_beta = (1 + beta^2) * precision * recall / (beta^2 * precision + recall)
FPR = FP / (FP + TN)
TPR = TP / (TP + FN)
Gini = 2 * (AUC_ROC - 0.5)
```

## Деревья

```text
Entropy H(p) = - sum_k p_k log p_k
Gini G(p) = 1 - sum_k p_k^2
Weighted impurity =
    (|R_left|/|R|) H(R_left) + (|R_right|/|R|) H(R_right)
Gain =
    H(R) - weighted_impurity
```

## Ансамбли

```text
Bagging regression:      a(x) = (1/N) sum_n b_n(x)
Bagging classification:  a(x) = argmax_y sum_n [b_n(x) = y]
Boosting composition:    a_N(x) = sum_{n=1}^N b_n(x)
Gradient boosting shift: s_i = - d/dz L(y_i,z) |_{z=a_{N-1}(x_i)}
MSE shift:               s_i = y_i - a_{N-1}(x_i)
Logistic shift:          s_i = y_i / (1 + exp(y_i a_{N-1}(x_i)))
```

# Что особенно помнить с 7-й лекции

- Выбор функции потерь задает, какие ошибки модель считает дорогими. MSE, MAE, Huber, MAPE и SMAPE ведут себя по-разному на выбросах и относительных ошибках.
- В линейной классификации ключевое понятие - отступ `M_i = y_i <w,x_i>`. Знак говорит о правильности, величина - об уверенности.
- 0-1 loss неудобна для оптимизации, поэтому используют верхние оценки: logistic loss, hinge loss, exponential loss.
- Accuracy опасна на несбалансированных выборках. Всегда смотреть баланс классов и матрицу ошибок.
- Precision отвечает за доверие к положительным предсказаниям, recall - за долю найденных положительных объектов.
- PR-кривая часто важнее ROC на сильно несбалансированных задачах.
- Логистическая регрессия связана с вероятностями и log-loss, SVM - с максимальным отступом и hinge loss.
- В многоклассовой классификации binary methods расширяют через one-vs-all или all-vs-all; метрики усредняют micro или macro способом.
- Деревья строятся жадно, легко ловят нелинейности, но переобучаются и неустойчивы.
- Бэггинг уменьшает разброс, особенно у неустойчивых моделей вроде деревьев.
- Случайный лес = бэггинг деревьев + случайный выбор признаков в каждой вершине.
- Бустинг строит модели последовательно и исправляет ошибки текущей композиции.
- Градиентный бустинг учит новую модель на антиградиенты функции потерь, а не просто на обычные остатки.
